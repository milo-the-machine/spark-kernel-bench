# spark-kernel-bench

Install-and-test study of the NVIDIA DGX Spark (GB10) kernels **7.0.0-1019** and **7.0.0-1024** against 6.17, run on four Sparks in November 2026. This repo holds the scripts and every raw receipt.

Write-up: https://al-engr.com/testing-dgx-spark-kernels.html

## TL;DR

| Kernel (all on driver 580.178.04) | RoCE / NCCL, 2 and 4 nodes | Real TP4 model | Single Spark | 6 h soak (2 h load + 4 h idle) |
|---|---|---|---|---|
| 6.17.0-1032 (control) | 0 failures | OK, outputs bit-identical | same | 0 resets |
| 7.0.0-1019 **with** `kho=off` | 0 failures | OK, bit-identical | same | 0 resets |
| 7.0.0-1019 **without** `kho=off` | **12 / 12 NCCL runs fail** (`ibv_reg_mr_iova2 ... Cannot allocate memory`) | **won't start** | not run | not run |
| 7.0.0-1024 | 0 failures | OK, bit-identical | same | 0 resets (one node had a USB-C monitor attached for 2 h) |

- If you run 7.0.0-1019 multi-node, `kho=off` must be in `/proc/cmdline` (NVIDIA's `nvidia-spark-grub-kho` package adds it). 7.0.0-1024 turns KHO off in its kernel config.
- `perftest` (`ib_write_bw`) **passes** on broken 1019. It registers host memory, while NCCL registers GPU memory. A passing perftest proves nothing here.
- 7.0.0-1024 did not reset for us, headless or with a USB-C monitor. Forum reports of 1024 resets exist (NVIDIA forum t/387397, t/387401). We could not reproduce them on this hardware.
- The only measured performance differences: RDMA 8-byte write latency of 2.5 µs on 6.17.0-1031/7.0.0-1019 vs 3.0 µs on 6.17.0-1032 and 3.35 µs on 7.0.0-1024. Nothing above the RDMA layer moved.
- Pick your container before you compare kernels: bf16 GEMM was 91 TFLOPS in NGC PyTorch 26.07 and 61 TFLOPS in 25.09 on the same box.

Full numbers: [`receipts/TABLE.md`](receipts/TABLE.md) (generated by `bench/aggregate.py` from the raw receipts).

## Which driver can boot which kernel

Prebuilt NVIDIA modules pin one exact driver version, and a host has one driver:

| Driver | 6.17 | 7.0.0-1019 | 7.0.0-1024 |
|---|---|---|---|
| 595.84 | 6.17.0-1031 | no | no |
| 595.99.02 | no | yes | yes |
| 580.178.04 (DGX OS 7.6.0 stock) | 6.17.0-1032 | yes | yes |

That is why every comparison arm runs 580.178.04. Gate every reboot on `modinfo -k <kernel> -F version nvidia` matching your installed driver, or the box comes up without a GPU.

## Running it on your own Spark

The scripts were written for our lab and **hard-code our node IPs** (`192.168.1.55-58` management, `10.0.0.x`/`10.0.1.x` RoCE rails, user `milo`, `/home/milo/kbench`). Edit those first.

Single Spark, the quickest useful check:

```bash
bash bench/node_facts.sh                        # what you're running
bash bench/build_llama.sh                       # needs Docker + nvcr.io/nvidia/pytorch:25.09-py3
# put gpt-oss-120b-MXFP4.gguf under ~/models/gpt-oss-120b-GGUF/, then:
bash bench/single_node.sh MYARM <your-spark-ip>
```

Two or more Sparks: copy `bench/` to every node, set the IPs in `run_fabric.sh` (the `MG` node list, the `--master_addr` RoCE IP and the `rdma_pair.sh` arguments), then `bash bench/run_fabric.sh MYARM 3`. Compare `receipts/MYARM` with ours using `python3 bench/aggregate.py receipts`.

## Safety notes that cost us something

- **Never allocate GPU memory until failure on a GB10.** `cudaMalloc` isn't charged to the cgroup, so the host OOM killer fires first. It took out our user session. `hog.py --probe` stops 8 GiB short of MemAvailable.
- **Test kernels with `grub-reboot`, not by changing the default.** DGX OS's `no-grubmenu.cfg` hides the menu. A `zz-*.cfg` with `GRUB_DEFAULT=saved` + `grub-reboot <entry>` gives you a one-shot boot that falls back by itself.
- **A 595 → 580 switch needs the HWE flavour meta** (`linux-modules-nvidia-580-open-nvidia-hwe-24.04`) in the install set. Otherwise apt satisfies `nvidia-dkms-580-open` with a Tegra or lowlatency-64k kernel's module package.

## Setup measured

4× DGX Spark (GB10, 128 GB), DGX OS 7.6.0, ConnectX-7 both rails through one MikroTik CRS804 switch, 4 KiB-page `nvidia` kernel flavour (the Dashboard default; `-64k` not tested). Containers: NGC PyTorch 25.09 for fabric/single-node tests; the vLLM lane image brings its own CUDA 13.0.
